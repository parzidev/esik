Şifreleme API’si

AES-256-GCM · JWE · JSON

API, içeriği sunucuda işler. Tarayıcı uygulaması şifrelemeyi bu cihazda yapar. Sunucu içerik veya anahtar kaydetmez; her işlemde yeni bir anahtar üretir.

Erişim

İşlem uçları bir Bearer erişim anahtarı ister. Bu, dosyaları açan KOZA1- anahtarından ayrıdır. Erişim anahtarı sunucudaki /docker/makeme/.secrets/api-token dosyasındadır; frontend’e veya herkese açık kodlara ekleme.

export KOZA_BASE_URL="https://makeme.parzi.dev"
# KOZA_API_TOKEN: sunucunun erişim anahtarı

POST/api/v1/encrypt

curl "$KOZA_BASE_URL/api/v1/encrypt" \
  -H "Authorization: Bearer $KOZA_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"text":"Merhaba","name":"not.txt"}'
{
  "jwe": "<şifreli JWE>",
  "key": "KOZA1-…",
  "algorithm": "A256GCM"
}

Dosya için text yerine data alanında dolgusu olmayan base64url verisi gönder. name ve mime alanları isteğe bağlıdır. Dosya adı da şifreli yükte tutulur.

POST/api/v1/decrypt

curl "$KOZA_BASE_URL/api/v1/decrypt" \
  -H "Authorization: Bearer $KOZA_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"jwe":"<şifreli JWE>","key":"KOZA1-…"}'
{
  "kind": "text",
  "name": "not.txt",
  "mime": "text/plain",
  "text": "Merhaba"
}

Dosya yanıtı text yerine base64url data içerir. Tarayıcı ve API çıktıları birbirinde açılabilir. Eski ESIK1- anahtarları da kabul edilir.

Heykel bağlamı

encrypt isteğinde isteğe bağlı sculpture alanı, 64 karakterlik bir SHA-256 heykel izi kabul eder. Bu iz HKDF anahtar türetimine girer ve şifreli yükte saklanır. API heykel render etmez. İzi göndermezsen yeni rastgele AES anahtarı kullanılır. Heykelden ek entropi veya güvenlik artışı iddia edilmez.
